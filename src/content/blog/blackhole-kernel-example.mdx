This is attempt #2 at writing an article that explains the entire blackhole chip and how to think about lowering kernels. We'll write a fast RMSnorm kernel. 

Writing a kernel for blackhole involves balancing a few constraints: 
- the FPU runs much faster (4-64x) than the SFPU, across all of its supported ops. 
- however, the FPU's max precision is tf32. it can accumulate in f32. 
- moving data from dst back into FPU narrows from f32 to 19-bits, losing precision for certain values. ((1/1024 survives, for example.))
- all SFPU operations use f32 arithmetic. this is the most accurate hardware on blackhole.

The most optimal kernel, in most cases, uses the FPU as much as possible while reducing the relative error compared to numpy float32 operations (only necessary operations go to SFPU). Even if the error is small in one hardware sequence, that will run hundreds of times, and the error will be magnitudes higher.

We'll start by assuming the all the tensors required are in the L1 of a core (this kernel will only run on one core). That includes the weight tensor, γ and the model activations x. 

Starting from the innermost operation, ${\sqrt{\frac{1}{d}\sum_{i=1}^{d} x_i^2}}$ is just an average of the activation tensor squared. We add a small bias $\epsilon = 10^{-5}$ after that to make sure that we cannot compute something close to $\sqrt{0}$. You can either do this on the FPU or the SFPU. We'll explore both options. 

## a note about allocations in srcA, srcB, and dst
It is useful to mentally split srcA, srcB, and dst into 128-element chunks, like in the tldraw diagram. The reason it's split up like that is because ELWMUL processes an aligned `8x16` block (128 elements) from srcA and srcB per instruction. Each ELWMUL needs a corresponding 128-element allocation in dst to accumulate its results. Instructions that process `4x16` blocks operate on 64 elements per pass. The SFPU mostly doesn't care about this 128-element allocation scheme (it can load and store from anywhere in dst), but it's easier to keep consistent memory allocation rules. 

## fpu 
The FPU includes an instruction that elementwise-multiplies `srcA` and `srcB`, and $x^2$ is just $x*x$. Let's load the activation tensor into both srcA and srcB, and run an ELWMUL across the entire tile. This requires 8 `ELWMULs` ((actually, this is 16, we need to run this twice to cover the whole mantissa of each element)) to cover the entire 64x16 tile. We'll set the accumulator to dst tile 1 (the first 64x16 chunk of dst, from top to bottom). All FPU operations post their output in dst.  

Now we have $x^2$ (f32) in dst tile 0. Remember that we always want to accumulate in f32 so that our operations retain as much precision as possible. If you keep the accumulator in bf16, then your multiplication will lose precision.

Next, we need to take the average. We need the SFPU and FPU for this. Blackhole has a weird way of doing averages. Since the FPU doesn't have any dedicated sum or division instructions, we need to get creative.  

Assume:
```python
srcA = Tensor.ones(64, 16)
srcB = Tensor.ones(1, 64) / 1024

srcB2 = srcB@srcA # (1,16)
srcA2 = Tensor.ones(16,1) # output of srcA
avg = (srcB2 @ srcA2) # (1,1)

avg.numpy() # 1
```

In Latex: 
$$
\operatorname{avg}(A)
= \left(\frac{1}{1024}\mathbf{1}_{64}^{\mathsf T}A\right)
  \mathbf{1}_{16}
= \frac{1}{1024}\sum_{i=1}^{64}\sum_{j=1}^{16}A_{ij}
$$

To execute this on sequence on blackhole hardware, we can use either the `GAPOOL` or `MVMUL` instruction. Both use a `16x16` chunk of srcA, but `GAPOOL` uses a `4x16` part of srcB while `MVMUL` uses an 8x16 chunk. Either one works here, but `MVMUL` computes four additional output rows that we don't need.
